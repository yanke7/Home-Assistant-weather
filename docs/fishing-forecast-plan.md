# Fishing forecasts in Atmosphere Weather

## Settings and scope

Add **Fishing forecasts** to the dashboard’s existing Settings page. The master switch defaults to off and applies to the Atmosphere configuration entry across browsers. Turning it off pauses fishing calculations and hides fishing on every location. Keep each location’s selections so turning it back on restores them.

With fishing enabled, show saved cities and lakes with an independent enable switch and an **Edit** button. Edit opens a Fishing settings panel for that location. Choose lake, river, pond or reservoir, then search and select species. Show the selected count and allow one to four species. Require at least one before enabling, and allow reordering. Store the water type and ordered species IDs on the existing location subentry. Use the saved coordinates and time zone. A nearby lake can be saved separately when its forecast should differ from the city’s. Only administrators change these shared settings, using the existing authenticated dashboard settings flow.

## Current weather and Fishing tab

When both switches are on, show a compact fishing summary near the top of current conditions for the selected location. Example with illustrative scores: **Good fishing now · Walleye 8/10 · Pike 7/10**. Show each selected species once, in the saved order. Use the current local hour’s score for the headline. A proposed default is “Good fishing now” if any selected species scores at least 7/10. When none qualifies, show “Fishing outlook is fair” or “Fishing outlook is poor.” Missing data should read “Fishing forecast unavailable.” Tapping the summary opens Fishing.

Add **Fishing** alongside Hourly and Daily and retain the existing Radar tab on narrow displays. In Fishing, pick a species and see today’s overall score, the next recommended local-time window and a seven-day outlook. Tapping a day opens its hourly scores and the main reasons for the best window. Show “Tomorrow” and the date explicitly for overnight planning. Use a compact two-by-two species layout on phones when needed. Keep the weather alert banner visible and the forecast tabs reachable alongside a configured camera or thermostat. If a user switches to a location without fishing while viewing Fishing, return to Hourly immediately.

## Forecast engine and entities

1. Extend the weather coordinator’s existing Open-Meteo request for enabled locations to include hourly pressure and cloud cover. Use seven local forecast days internally. Preserve elapsed hours needed for the current day's mean and preceding hours needed for pressure trends. Keep the weather card’s existing 48-hour display payload separate from the fishing calculation. Calculate once per location refresh and reuse the results for every selected species.
2. Implement a pure scoring module with versioned species profiles and normalized water-type weights. Score each hour using temperature, cloud, pressure trend, wind, precipitation, dawn/dusk and lunar factors. Select a maintained astronomy implementation that can calculate local lunar rise, set and upper/lower transit, verify against reference examples, and include upstream MIT attribution for reused profiles or code. Test no-rise/no-set cases. A missing astronomy event should omit that factor and renormalize the available weights. Missing core weather data makes the affected score unavailable.
3. Keep three concepts distinct: the current hour’s score, each local day’s mean score, and the highest-average three consecutive hourly periods. Represent windows as start-inclusive and end-exclusive timestamp pairs. For example, a window covering the 6, 7 and 8 AM hours ends at 9 AM. Skip expired windows when finding the next one. Explain in the detail view that forecast air temperature is a proxy for water temperature, and the score is a conditions rating.
4. Return fishing data for the selected location through the existing snapshot endpoint. Expose native entities under its existing device per selected species: current score, daily score, next window start/end timestamps and a window-active binary sensor. Use location subentry ID and species ID for stable unique IDs. Master-off makes existing fishing entities unavailable and preserves their identity. Explicit species removal retires that species’ entities. No open dashboard is required for automations.
5. Translate fishing settings, species display names, ratings and accessibility labels using the dashboard’s existing language support. Format time, date and units using the selected location and dashboard preferences.

## Delivery and acceptance

Build in three increments: shared settings and persistence, forecast engine and entities, then hero summary and forecast tab. Verify a clean install, an upgrade with existing locations, and settings persistence across devices and restarts. Test two enabled locations with different species plus a disabled city, one and four species, global disable/re-enable, unavailable or stale forecasts, DST transitions, polar daylight, expired windows and scoring boundaries. Check portrait and landscape layouts with six custom weather boxes, camera, thermostat, alerts and the Star Trek theme. Validate a simulated notification when a species enters a good window and run the integration tests, Hassfest and HACS checks before release.
